# 0005. 運用規約（conventions）の正本を「規約課題」に置く

- 日付: 2026-09-03
- ステータス: 採用

## コンテキスト
Linear の思想を取り込む conventions 機能では、`conventions.yaml` を apply の入力とする一方、
`conventions show` や MCP ツール、issue コマンドの警告が規約を読む必要がある。
MCP サーバーは stateless で複数ユーザーから使われるため、ローカルファイルを読み出しの正本にできない。
規約は人間も Backlog 上で読める場所に置き、更新できる必要がある。

## 決定
プロジェクトごとに種別「規約」の課題を 1 件だけ置き、その説明欄に運用ガイド・用語集と YAML コードブロックを
持たせる。作成は `CreateIssue`、更新は `UpdateIssue` を使う。読み出し側は種別「規約」の課題を検索し、
0 件なら規約未導入として従来どおり動き、2 件以上なら exit 2 とする。規約課題は閉じないため、
stale / blockers / workload / health の分析対象から種別「規約」を除外する。

## 検討した代替案
- Backlog Document: 更新・削除 API がなく、apply のたびに新規作成が積み上がる。却下
- Backlog Wiki: 更新 API はあるが運用で使っておらず、誰も見ない場所に正本を置くことになる。却下
- Backlog 外（git 管理 + URL を MCP の環境変数で指定）: 運用は素直だが、人間が Backlog 上で読めず、
  MCP デプロイ側の設定が増える。却下

## 影響
- 規約の変更履歴が Backlog の更新履歴として残り、議論はコメントで行える
- 閉じない課題が各プロジェクトに 1 件存在し、分析系に種別除外の実装が必要になる
- conventions のスキーマは種別「規約」を必須とする
