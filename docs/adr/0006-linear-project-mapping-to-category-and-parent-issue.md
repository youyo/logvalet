# 0006. Linear の Project を Backlog の「カテゴリ + 案件親課題」に対応付ける

- 日付: 2026-09-03
- ステータス: 採用

## コンテキスト
運用上、Backlog プロジェクトは顧客ごとに作られ、案件はカテゴリで分けられている。この形は変えない。
Linear の Project（数週間の取り組み）は Lead 1 人・期間・状態・説明テンプレートを持つが、
Backlog のカテゴリはいずれも持てない。

## 決定
案件 = カテゴリ + 種別「案件」の親課題とする。親課題の担当者を Lead、開始日/期限日を期間、
状態を進行状況、種別テンプレートで Context & Goals / Scope / Acceptance criteria を持たせる。
課題は案件カテゴリをちょうど 1 つ持ち、親子課題機能で案件親課題の子にする。
Initiative は Backlog に対応物を作らず、conventions.yaml 内のプロジェクトごとの順序付きリストで持つ。
優先度は 高・中・低 固定のまま、意味を組織の言葉で定義する。

## 検討した代替案
- マイルストーンを案件の器にする: 期間と説明はあるが担当者と説明テンプレートを持てず、Lead を強制できない。却下
- Backlog プロジェクト = Linear Project とする: 顧客ごとプロジェクトの運用と衝突する。却下
- Initiative を横断プロジェクト（INIT）の課題で持つ: Initiative はプロジェクトごとに異なるため横断の器が不要。却下
- 優先度に 4 段階目を足す: Backlog はカスタマイズ不可。却下

## 影響
- apply はカテゴリと親課題を 1:1 で作り、欠けを検知する
- 「1 案件に属する」は API で強制できないため、health の曖昧さ検知で補う
- `issue create / update --engagement` で親課題とカテゴリを同時設定する
- 過去課題の親子付け替えはスコープ外
